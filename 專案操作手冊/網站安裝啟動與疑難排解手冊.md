# 網站安裝、啟動與疑難排解手冊

本手冊適用於 `umc-project` 整合版網站。網站由三個部分組成：XAMPP 的 MySQL/MariaDB 保存帳號與報告、Node.js API 負責資料存取與呼叫 Python、Expo Web 顯示操作介面。

```text
瀏覽器（localhost:8081）
        ↓
Node.js API（localhost:3000）
        ├─ MySQL/MariaDB：帳號、自選股、報告
        ├─ Yahoo Finance：市場行情
        └─ 程式/：Python 策略回測
```

## 一、第一次安裝前準備

需要安裝：

- XAMPP（使用其中的 MySQL/MariaDB；Apache 用來開啟 phpMyAdmin）
- Node.js 22 LTS，或至少 Node.js 20.19.4
- Python 3.12 以上及 `uv`（需要執行真實回測時使用）

安裝 Node.js 時，請從官方網站選擇 Windows x64 的 **Windows Installer (.msi)**。安裝選項保持預設，確認包含 npm 及 Add to PATH；不需要 Docker 或 ZIP 版本。

安裝後完全關閉並重新開啟 VS Code，再確認：

```powershell
node -v
npm -v
```

`node -v` 應顯示 `v22.x.x`，或至少不低於 `v20.19.4`。

## 二、建立整合版資料庫

1. 開啟 XAMPP Control Panel。
2. 啟動 Apache 與 MySQL；兩列變成綠色即表示已啟動。
3. 按 MySQL 旁的 Admin，或開啟 `http://localhost/phpmyadmin/`。
4. 點 phpMyAdmin 上方的「匯入」。
5. 選擇專案根目錄的 `建立整合版資料庫.sql`。
6. 保持其他選項為預設，按「匯入」或「執行」。

SQL 會自動建立 `umc_topic_integrated`，不必先手動新增資料庫。成功後左側應看到此名稱，展開後可看到 `users`、`favorite_stocks`、`reports` 等資料表。

這份 SQL 僅供第一次建立全新資料庫。若 `umc_topic_integrated` 已經存在，請勿重複匯入，以免出現「資料庫已存在」錯誤。

## 三、設定 API 的資料庫連線

資料庫設定檔應位於：

```text
前端/server/.env
```

注意，`前端/.env.example` 是前端 API 網址範例，不是資料庫設定檔。

若 `前端/server` 只有 `.env.example`：

1. 複製 `前端/server/.env.example`。
2. 將複製出的檔案重新命名為 `.env`。
3. 確認不是 `.env.txt`。

基本內容如下：

```env
PORT=3000
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=
DB_NAME=umc_topic_integrated
JWT_SECRET=請自行設定一段較長且不公開的字串

PYTHON_BACKTEST_ROOT=../../程式
PYTHON_EXECUTABLE=
BACKTEST_TIMEOUT_MS=17200000
BACKTEST_TICK_SOURCE=sinopac
BACKTEST_INITIAL_CAPITAL=100000

YAHOO_MARKET_CACHE_MS=20000
YAHOO_SYMBOL_CACHE_MS=15000
YAHOO_HTTP_TIMEOUT_MS=12000
YAHOO_HOT_LIMIT=8
```

若 XAMPP 的 `root` 沒有設定密碼，`DB_PASSWORD=` 後方保持空白。若有密碼，請填入實際密碼。`.env` 內可能包含密碼與金鑰，不要上傳到公開儲存庫或貼到報告中。

## 四、安裝網站套件

在 VS Code 選擇「終端機 → 新增終端機」，執行：

```powershell
cd C:\Users\yunso\OneDrive\桌面\專題0928\umc-project\前端
npm install
cd .\server
npm install
```

安裝成功通常會顯示 `added ... packages` 或 `up to date`。`npm audit` 顯示 moderate vulnerabilities 不會阻止本機啟動，不要在不清楚影響時直接執行 `npm audit fix --force`。

一般只有第一次安裝、套件清單更新，或 `node_modules` 被移除後才需要重新執行。

## 五、啟動網站

每次使用時依照以下順序：

1. 開啟 XAMPP，啟動 MySQL。需要 phpMyAdmin 時也啟動 Apache。
2. 雙擊專案根目錄的 `啟動API.cmd`。
3. 雙擊專案根目錄的 `啟動前端.cmd`。
4. 兩個終端機視窗都保持開啟。
5. 使用 Chrome 開啟 `http://localhost:8081`。

API 成功時會顯示：

```text
AI 股票系統 API 已啟動：http://localhost:3000
資料庫：umc_topic_integrated
```

前端成功時會顯示 `Web Bundled`，瀏覽器會進入 `http://localhost:8081/login`。

第一次使用請按「註冊新帳號」，輸入姓名、電子郵件與至少 6 個字元的密碼，再回登入頁登入。

## 六、確認服務是否正常

API 健康檢查：

```text
http://localhost:3000/api/health
```

看到 JSON 中的 `"ok": true`，代表 API 與資料庫連線正常。

網站入口：

```text
http://localhost:8081
```

三個必要服務如下：

| 服務 | 用途 | 關閉後的影響 |
|---|---|---|
| XAMPP MySQL | 帳號、自選股、報告資料 | 無法註冊、登入或讀寫資料 |
| Node.js API | 串接資料庫、行情與 Python | 網站可開，但資料功能失敗 |
| Expo Web | 顯示網站 | `localhost:8081` 無法開啟 |

## 七、關閉與下次啟動

使用完畢後：

1. 在前端與 API 終端機按 `Ctrl+C` 停止服務，或關閉視窗。
2. 回到 XAMPP 停止 MySQL；若有啟動 Apache，也一併停止。

下次使用不必重新安裝 Node.js、npm 套件或匯入 SQL，只要重新啟動 MySQL、API 與前端。

## 八、常見問題

### 1. `Cannot find module 'dotenv'`

原因：`前端/server` 的 Node.js 套件尚未安裝。

處理：

```powershell
cd C:\Users\yunso\OneDrive\桌面\專題0928\umc-project\前端\server
npm install
```

完成後重新啟動 API。

### 2. 大量 `npm warn EBADENGINE`

原因：Node.js 版本過舊。React Native 0.81.5 與 Metro 需要至少 Node.js 20.19.4。

處理：安裝 Node.js 22 LTS，完全關閉並重新開啟 VS Code，再用 `node -v` 確認版本。只重新開終端分頁有時仍會沿用舊環境。

### 3. `npm ci` 顯示 package.json 與 package-lock.json 不同步

可能會看到：

```text
npm ci can only install packages when package.json and package-lock.json are in sync
```

原因：套件清單已修改，但鎖定檔尚未同步。

處理：在對應資料夾執行 `npm install`，不要繼續重試 `npm ci`。

### 4. `http://localhost:3000` 顯示 `Cannot GET /`

這不是 API 壞掉。後端沒有設定根路徑 `/` 的頁面。請改開：

```text
http://localhost:3000/api/health
```

網站本身在 `http://localhost:8081`。

### 5. `localhost:8081` 顯示 `ERR_CONNECTION_REFUSED`

原因：前端服務尚未啟動，或啟動後已因錯誤結束。

可在終端機手動啟動並查看錯誤：

```powershell
cd C:\Users\yunso\OneDrive\桌面\專題0928\umc-project\前端
npm run web
```

終端機顯示 `Web Bundled` 後重新載入瀏覽器。終端機不可關閉。

### 6. 網站能開啟，但無法註冊或登入

依序確認：

- XAMPP 的 MySQL 是否為綠色啟動狀態。
- `前端/server/.env` 的 `DB_NAME` 是否為 `umc_topic_integrated`。
- MySQL 密碼是否與 `DB_PASSWORD` 相同。
- `http://localhost:3000/api/health` 是否顯示 `"ok": true`。
- API 終端機是否有資料庫錯誤訊息。

### 7. `umc_topic_integrated` 已存在

代表資料庫可能已經建立完成。不要重複匯入首次安裝 SQL。先展開資料庫檢查是否已有資料表；若資料表存在，直接設定 `.env` 並執行健康檢查。

### 8. 連接埠已被占用

若 API 顯示 3000 已被使用，或 Expo 改用其他連接埠，先檢查是否已經開了一個相同服務的視窗。關閉重複的舊視窗後再啟動。若 Expo 自動使用其他連接埠，請以終端機顯示的網址為準。

### 9. 行情無法載入

首頁行情依賴 Yahoo Finance 與網路連線。先確認 API 和網路正常，再查看 API 終端機的錯誤。資料庫正常不代表外部行情一定可取得。

### 10. 執行回測失敗

網站能開啟只代表前端、API 與資料庫正常。真實回測還需要：

- Python 3.12 以上
- 在 `程式` 資料夾執行過 `uv sync`
- `程式/.env` 中有可用的行情來源設定或憑證
- `PYTHON_BACKTEST_ROOT=../../程式`

可先完成網站註冊、登入與行情檢查，再另行設定 Python 回測環境。

## 九、不要混淆的檔案與位置

| 路徑 | 用途 |
|---|---|
| `前端/.env.example` | 前端連接 API 的網址範例 |
| `前端/server/.env` | API、MySQL、Python 與行情設定 |
| `建立整合版資料庫.sql` | 首次建立 `umc_topic_integrated` |
| `前端/server/python-backtest/` | 保留的舊引擎，不是整合版主要回測核心 |
| `程式/` | 整合版實際使用的 Python 回測與研究核心 |
| `啟動API.cmd` | 啟動 localhost:3000 |
| `啟動前端.cmd` | 啟動 Expo Web，通常是 localhost:8081 |
