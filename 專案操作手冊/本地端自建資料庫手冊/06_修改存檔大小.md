# 06　調整 MySQL 報告傳輸大小

網站會將完整回測 JSON 存入 `reports.report_content`。若報告接近或超過 MySQL 的 `max_allowed_packet`，網站會顯示「報告大小超過目前 MySQL 連線的傳輸上限」。這代表回測已完成，但報告尚未寫入資料庫。

## 一、永久調整 XAMPP MySQL

1. 先關閉專案的 API 視窗。
2. 在 XAMPP Control Panel 停止 MySQL。
3. 按 MySQL 右側的 `Config`，選擇 `my.ini`。
4. 找到 `[mysqld]` 區段。
5. 若該區段已有 `max_allowed_packet`，將它改為下列數值；若沒有，就在 `[mysqld]` 下新增：

```ini
max_allowed_packet=64M
```

請確認設定寫在 `[mysqld]` 區段。只修改 `[mysqldump]` 或 `[client]` 下的同名設定，不會提高網站連線所使用的伺服器上限。

6. 儲存 `my.ini`。
7. 回到 XAMPP 重新啟動 MySQL。
8. 重新啟動專案 API，讓連線池建立新連線。

## 二、確認設定生效

開啟 phpMyAdmin，點上方「SQL」，執行：

```sql
SHOW VARIABLES LIKE 'max_allowed_packet';
```

64 MB 通常會顯示為 `67108864`。若仍接近 4 MB，代表修改了錯誤的 `my.ini`、設定不在 `[mysqld]`，或 MySQL 尚未重新啟動。

## 三、重新執行回測

確認上限生效後，回到網站重新按「執行回測」。程式會重新產生報告並寫入資料庫。

資料表使用 `LONGTEXT`，足以保存此類報告；此錯誤限制的是單次 MySQL 傳輸封包，不是欄位容量。程式使用資料庫交易，傳輸上限檢查失敗時會回復該次寫入，不會留下缺少完整報告的半套紀錄。

網站訊息中顯示的暫存資料夾可供除錯，但平常不需要手動匯入。修正設定後重新執行回測即可。
