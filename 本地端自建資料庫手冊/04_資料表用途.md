# 04　資料表用途

## 原本專題資料表

| 資料表 | 保存內容 |
| --- | --- |
| `users` | 網站使用者 |
| `stocks` | 股票名稱、市場及產業 |
| `analysis_records` | 每次策略分析的基本資料 |
| `backtest_results` | 報酬率、勝率、回撤、Sharpe及成本 |
| `reports` | 完整HTML回測報告 |
| `model_predictions` | 模型預測資料 |
| `favorite_stocks` | 使用者自選股票 |
| `market_data_days` | 行情資料日期完整度 |
| `market_ticks` | 原始Tick行情 |
| `technical_indicators` | 技術指標資料 |

## 老師要求使用的研究資料表

| 資料表 | 可以呈現的功能 |
| --- | --- |
| `research_runs` | 股票、回測期間、本金、參數版本 |
| `strategy_metrics` | 六策略比較、報酬排名、風險最低策略 |
| `regime_metrics` | 上漲、盤整、下跌階段的策略表現 |
| `daily_risk` | 每日資產、每日損益及最大回撤 |
| `trade_records` | 買賣時間、價格、股數、手續費與交易稅 |

前端網站可以先查詢 `research_runs` 最新批次，再依 `run_id` 查其他四張表，便能組成策略研究工作台。

## 兩種本機資料庫不要混淆

- `data/market_data.sqlite3`：行情與5分K，提供回測運算。
- `data/research.sqlite3`：本機研究成果，提供目前的工作台。
- XAMPP MariaDB 的 `ai_stock_system`：未來提供正式前端與組員共同查詢。

SQLite 檔案不能直接當成 MariaDB 資料表使用，需要透過同步程式轉換。
