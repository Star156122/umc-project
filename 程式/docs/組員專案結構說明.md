> 2026-09-25 新增策略研究工作台：執行 `uv run python research.py serve`，用瀏覽器開啟 http://127.0.0.1:8765 。完整操作與新增檔案說明請看 [策略研究工作台](guides/策略研究工作台.md)。研究網頁在 `web/research.html`、分析功能在 `trading_system/research.py`、操作流程在 `scripts/research.py`，資料存放在 `data/research.sqlite3`；本次參數另存在 `configs/frozen_baseline.json`。

**下面的路徑都從「程式」資料夾開始。執行指令前，也請先進入「程式」資料夾。**

最外層和 `scripts/` 裡有些檔名一樣，是為了保留大家原本的操作方式。例如執行最外層的 `run_batch.py`，就會啟動 `scripts/run_batch.py` 裡的功能。要改程式內容時，主要修改 `scripts/` 或 `trading_system/` 裡的檔案。

目前 `backtest.py` 仍包含多種回測相關功能，尚未全部拆成小檔案。

## 三、程式怎麼執行？

第一次拿到專案時，先把 `.env.example` 複製成 `.env`，依照自己要使用的功能填入設定。只看已經產生的 HTML 報告，不需要先設定金鑰。

以下指令在「程式」資料夾的終端機執行。

安裝專案需要的套件：

```powershell
uv sync
```

執行一個策略。程式會讀取 `backtest_config.json` 裡的 `active_profile`，這個欄位代表「這次要執行哪個策略」：

```powershell
uv run python main.py
```

一次執行六個策略，並產生總比較報告：

```powershell
uv run python run_batch.py
```

只更新行情資料：

```powershell
uv run python update_data.py --profile 2303_ma
```

替 `reports/2303` 裡現有的個別報告加入 AI 分析。需要設定可使用的 AI 服務金鑰；已有分析的報告會沿用原本的內容：

```powershell
uv run python enrich_existing_reports.py reports/2303
```

檢查程式功能是否正常：

```powershell
uv run python -m unittest discover -s tests -v
```

`reports/2303/strategy_comparison_20260911_145229/strategy_comparison.html`

`reports/2303/20260911_145150_2303_vote_2303_vote_optimized_2026-01-01_2026-06-30/report.html`

找其他策略時，先看資料夾名稱裡的英文，再開裡面的 `report.html`：

| 名稱中的英文 | 策略 |
| --- | --- |
| `ma` | 均線策略 |
| `rsi` | RSI 動能策略 |
| `macd` | MACD 策略 |
| `bollinger` | 布林通道策略 |
| `breakout` | 區間突破策略 |
| `vote` | 三指標多數決策略 |

每份個別報告裡的檔案用途：

| 檔案 | 用途 |
| --- | --- |
| `report.html` | 用瀏覽器看的報告，包含圖表、績效和 Gemini 分析，展示給老師主要開這個 |
| `trades.csv` | 每次實際模擬成交的時間、價格、股數、手續費和交易稅 |
| `signals.csv` | 策略何時發出買賣訊號，以及觸發原因 |
| `pnl.csv` | 每筆買進、賣出配對後的獲利或虧損 |
| `summary.json` | 給程式讀取的績效摘要，用來整理比較結果 |
| `llm_report.json` | 保存 AI 產生的分析文字及相關資訊 |

## 五、要改功能時，應該改哪裡？

- 調整股票、日期、本金或策略數值：`backtest_config.json`。
- 修改策略判斷、模擬成交或網頁報告：`trading_system/backtest.py`。
- 修改 AI 要分析的內容、使用方式或文字呈現：`trading_system/llm_analysis.py`。
- 修改六策略的執行流程：`scripts/run_batch.py`。
- 修改行情下載及更新流程：`scripts/update_data.py`。

## 六、分享檔案及整理報告時要注意

- `.env` 裡可能有券商、資料庫或 Gemini 金鑰，不要傳給組員。給組員的是 `.env.example`，讓每個人填自己的設定。
- `data/market_data.sqlite3` 是已經下載好的行情資料。保留它，才能減少重新下載資料的時間。
- `reports/` 裡的正式報告盡量不動。只有整份資料夾的檔名與所有檔案內容完全相同，才刪除舊版、保留較新的版本；只要有差異就兩份都留著。
- `database/exports/` 是讓組員將資料放進資料庫的檔案，和用瀏覽器看的報告不同。
