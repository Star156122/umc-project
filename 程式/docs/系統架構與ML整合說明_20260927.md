# 系統架構與 ML 整合說明

## 這次完成什麼

這次保留原本技術策略研究，另外新增一條獨立的機器學習研究線。沒有製作 APP，也沒有把模型輸出直接變成買賣訊號。

資料流程如下：

```text
market_data.sqlite3 的 5 分 K
  → 日期鎖與資料角色檢查
  → 缺值、重複值、異常 OHLCV 檢查
  → 使用過去資料計算 15 個特徵
  → 依時間切成 Train / Validation / Test
  → 只用 Train 做標準化
  → Random Forest / XGBoost / GRU 公平比較
  → JSON / CSV / HTML / SQLite
  → 後端 API
  → 結構化 AnalysisRecord
  → LLM 只能根據紀錄寫白話說明
```

## 三個模型在做什麼

三者都回答同一道題目：看完目前與前 23 根 5 分 K 後，約 60 分鐘後的收盤價是否比目前高。

- Random Forest：由很多棵決策樹共同投票，適合先建立容易解釋的基準。
- XGBoost：逐步修正前面樹模型的錯誤，常用於表格型資料。
- GRU：依照 K 棒順序讀取資料，用來測試時間先後是否帶來額外資訊。

目前不以單一最高分選出正式模型，也不掃描大量參數。這輪目的是建立公平 baseline。

## 資料清理規則

- 同股票、同時間重複資料只留第一筆並計數。
- 開高低收小於等於零、成交量小於零、高低價關係不合理時剔除並計數。
- 技術指標暖機期間的缺值不補造，直接略過。
- K 棒不連續或跨交易日的序列不用，也不人工補 K 棒。
- 標準化的平均值與標準差只從 Train 計算，再套到 Validation 與 Test。

## 輸出位置

- 網頁：`exports/ml_baseline_latest.html`
- 完整數字：`exports/ml_baseline_20260927/results.json`
- 模型比較表：`exports/ml_baseline_20260927/model_summary.csv`
- 各股票比較：`exports/ml_baseline_20260927/per_stock_metrics.csv`
- 資料清理紀錄：`exports/ml_baseline_20260927/data_audit.json`
- ML 研究資料庫：`data/ml_research.sqlite3`
- 統一分析紀錄：`exports/unified_analysis_latest.json`
- 給 LLM 的固定資料：`exports/unified_llm_payload_latest.json`

本機研究網站啟動後可用 `/ml-latest` 看報告，用 `/api/ml/latest` 與 `/api/analysis/latest` 取 JSON。

## 研究限制

本次使用的 14 檔股票與 2026 年上半年都已經被看過，因此分類為 `ml_development_seen`。它能幫忙確認程式流程與模型差異，不能冒充 Clean Validation。2025/07/01～2025/12/31 Holdout 仍完全鎖定。
