# 股票回測專題固定研究規範

依使用者 2026/09/26 指示建立。適用未來所有新增策略、策略修改、最佳化、回測、報告與版本比較；除非使用者明確變更，持續有效。

## 研究方向與順序

六策略逐笔交易與虧損診斷 → 各別提出有交易理由的改善 → 一次只改必要部分 → 相同開發資料跨股票重測 → 比較改善前後 → 選出候選 → 規則全部確定以前鎖住保留資料 → 使用者明確要求最終驗證才使用。

不先限縮產業，不因聯電2303表現好就推論半導體適合。產業適配須另立實驗，同產業多檔驗證。MACD與多數決是候選，不代表放棄其他策略的診斷。

|策略|優先研究問題與改善方向|
|---|---|
|MA|假趨勢、追高與落後訊號；先研究趨勢強度、均線乖離、進場位置，不只調停損停利。|
|RSI|交易過多、成本侵蝕；減少沒有優勢的進場，研究趨勢、冷卻與訊號確認，不反覆調RSI數值美化結果。|
|MACD|盤整反覆交叉；保留原邏輯，研究日線趨勢或合理盤整濾網。|
|布林通道|先檢查原進場邏輯是否有優勢，不靠出場硬救；允許保留為失敗對照。|
|區間突破|假突破；研究突破幅度、量能、前期盤整、趨勢，不只突破前高就買。|
|多數決|弱勢行情誤進場；研究日線確認與合理出場確認，仍需真正獨立驗證。|

上述問題是研究假設，須用逐筆交易驗證，不自動當成已證實因果。

## 禁止依單一股票調參

主要規則使用共同邏輯跨股票測試。禁止為2303、2330或其他個股設專屬最佳參數再宣稱有效。只對部分股票有效時記錄原因，不為救單一股票修改參數。不大量掃參數選最高報酬，不刪失敗結果，不不斷加條件直到開發資料獲利。每一新增條件都要回答「解決哪個具體交易問題？」。

## Holdout Lock

2025/07/01～2025/12/31 為未使用保留資料。設定在 `configs/holdout_policy.json`，共用防線在 `trading_system/research_guard.py`。

開發期間禁止用它調參、選策略、比較版本、最佳化、除錯績效、決定風控，禁止查看報酬、勝率、Sharpe、回撤或任何影響選擇的結果；不得產圖後回頭修改，禁止直接或間接洩漏。暖機資料也不得跨入該期間。

「再跑一次、測試新策略、比較策略、最佳化、產生新版HTML、全部跑」均只使用開發資料。指令與此規則衝突時提醒使用者，拒絕執行；不自動解鎖。

只有「開始最終Holdout Test」、「使用保留資料做最終驗證」或同樣明確的指示才授權正式驗證。一般入口沒有解鎖旗標或環境變數。目前不提供可自動解鎖的正式測試入口。

正式測試前先凍結程式雜湊、參數、候選版本、股票、成本模型、指標與判定標準，保存授權與執行紀錄；第一次資料存取就標示已使用（即使中途失敗），保存全部結果。不能因結果差而修改後再測同一Holdout。根據結果修改的新策略，須另外找從未參與開發的驗證資料，期間先取得使用者確認。

## 每次改善必備紀錄

- 原始版本、修改內容、理由、針對的虧損問題、參數與程式快照。
- 同股票、同期間、同成本與資金規則下的前後比較：交易次數及變化、Gross PnL、Net PnL、交易成本、勝率、平均獲利、平均虧損、Profit Factor、Max Drawdown、Sharpe Ratio。
- 跨股票改善數、每檔分布、是否僅一檔拉高平均；拿掉2303或其他任一檔後的結果。
- 勝率變高但交易大減須一起解釋；毛損益正、淨損益負優先判定交易效率／成本問題；毛損益負先查進場邏輯，不先調成本或停損。
- 保留原版、修改版、買進持有與現金基準，以及所有失敗结果。缺資料的指標註明缺少，不補造數字。

## 真正要回答的問題

策略在哪些行情失敗？虧損來自進場、出場、成本或市場型態？針對原因改善後能否跨股票一致改善？哪些策略泛化較好？最後是否在未參與開發的Holdout仍有效？目的不是把六種策略全部調成獲利。

## 2026/09/26 研究治理補充（後續優先適用）

專案核心判定順序為「泛化能力 > 開發期最高報酬率」。資料分成四種角色：

1. `development`：目前是 2026/01/01～2026/06/30；可用來診斷、提出假設與少量拆項實驗，但已反覆查看，不能當獨立驗證。
2. `validation_clean`：從未參與設計、績效未被查看的新股票。候選規則必須先凍結，第一次查看後不可再拿同一批資料修改策略。
3. `validation_seen`：曾跑過、曾查看、曾影響策略修改，或無法確定是否乾淨的資料。只可作歷史、行情切換與補充研究。
4. `holdout`：2025/07/01～2025/12/31，仍為 `access=forbidden`，只有使用者明確宣布最終 Holdout Test 才能啟動正式、可稽核流程。

固定流程：Baseline → 逐筆交易診斷 → 事前登記假設 → 每輪一個主要修改 → Development 拆項 → 跨股票比較 → PASS／FAIL／INSUFFICIENT → Freeze → Clean Validation → 最終 Holdout。同一策略、同一主要問題原則上只做 1～2 輪有明確理由的開發，不從舊資料持續榨績效。

每次實驗開始前必須登記：`experiment_id`、策略、Baseline、觀察到的問題、針對的失敗交易、單一修改、交易理由、預期改善、可能犧牲、股票、期間、資料角色、Holdout 狀態、規則是否事先固定及是否含可掃描參數。禁止先跑很多版本再補理由。

每次報告除資金、毛損益、淨損益、報酬、交易數、勝率、平均獲利／虧損、PF、賺賠比、最大回撤、Sharpe、交易成本及成本／毛利外，至少要列平均數、中位數、改善股票數、獲利股票數、不含2303改善中位數、各股票報酬與交易數。1～4筆交易標成 `INSUFFICIENT`；交易大量減少也要檢查是否只是刪除樣本造成表面改善。

Development 與 Clean Validation 必須分開報告。Clean Validation 不要求每檔獲利，重點是中位數、PF、成本、回撤、樣本量，以及是否依賴單一股票。若驗證失效，先判定可能過度配適或標的適配受限；不得立刻用同一批新股票回頭調參。若因此修改，整批股票立即轉成 `validation_seen`，下一版另找未看過資料。

## 目前候選版本狀態

- MACD 前一輪「原邏輯 + 前一日日線趨勢確認」：`RESEARCH_CANDIDATE / BASELINE`。不得再用原六檔調整，下一步只能用凍結版本做 Clean Validation。
- MACD 早期價格延續版（K0訊號、K1收盤突破K0高點、K2開盤成交）：`REJECTED`。交易由86降至19，平均報酬由3.96%降至-1.81%，PF由1.35降至0.50，須保留為失敗研究結果。
- 三指標多數決修改版 + 同一早期價格延續確認：`FROZEN_RESEARCH_CANDIDATE`。Development 結果為平均報酬9.70%、中位數1.25%、4/6獲利、51筆交易、PF 2.22、平均回撤7.72%、Sharpe 0.409；2412僅2筆、2002僅4筆，這兩檔證據不足。它尚未通過 Clean Validation 或 Final Holdout，不能稱正式策略。

## 專案檔案治理

研究分類與登記表以 `research/` 為入口：`current` 放目前狀態，`development` 放原六檔索引，`validation_clean` 放尚未查看的新股票計畫，`validation_seen` 放已查看資料索引，`archive` 收錄舊版與失敗實驗索引，`holdout` 只放鎖定說明。既有報告先保留原路徑，避免程式、首頁與文件連結失效；分類由 Registry 與索引完成。

歷史回測、失敗策略、舊HTML／JSON／CSV／Markdown與曾用來判斷策略的資料不得直接刪除。Cache、`__pycache__`、測試報告、完全可重建中間檔及內容完全相同的重複檔，只能先列入建議刪除清單，等待使用者確認。

目前整理工作的固定指示：先不要回測，先根據以上規範整理目前專案資料夾、建立 dataset/experiment registry，並提出 clean validation 可用股票清單與建議刪除清單，完成後先讓我確認。
