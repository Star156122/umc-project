# 網站新增股票資料接入規範

更新日：2026-11-14。這是資料接入與格式驗收流程，不是回測授權，也不修改交易規則。

## 基本原則

資料不會因為複製到某個資料夾就自動接上。每檔股票都必須先確認來源、日期與格式，再登記後端設定並通過唯讀預檢。未標記 `QA_PASSED` 的股票不會出現在網站核准清單，API 也會拒絕執行。

四類必要資訊如下。它們是四種邏輯資料，不一定是四個獨立檔案；大盤指數可共用，股利事件也可直接登記在設定檔。

|資料|用途|目前支援格式|
|---|---|---|
|股票5分K行情|進出場、技術指標與暖機|SQLite `market_kbars`|
|三模型預測|RF、XGBoost、GRU 的共同覆蓋與各自 Gate|固定模型 JSON 或時間順序 OOF CSV|
|大盤指數|市場濾網及官方交易日順序|含 `date`、`close` 的 JSON 陣列|
|現金股利|除息調整、應收與發放現金|含 `events` 的 JSON，或設定檔內嵌事件|

## 接入順序

1. **先盤點現有資料**：只檢查使用者指定的資料位置，確認是否已有目標股票與期間；不要因檔名相似就假設內容正確，也不要立刻重抓。
2. **補齊缺少資料**：保存行情、指數、股利及模型預測的來源與取得時間。不得以其他股票、ETF或代理預測替代；不得使用回測期間的未來資料訓練模型。
3. **登記後端設定**：同時更新 `hybrid/config/web_main_strategy_v1.json` 的 `stock_universe` 與 `datasets`。每檔至少登記 `stock_name`、`qa_status`、`warmup_start`、可回測起訖日期、資料路徑及 `prediction_kind`。只改日期不算完成接入。
4. **執行唯讀預檢**：在 `程式` 目錄執行 `python scripts/preflight_web_main_datasets.py 股票代號`。它只檢查資料與模型覆蓋，不計算策略績效。
5. **通過後才開放**：預檢成功後，該檔設定才能標記 `qa_status=QA_PASSED`。網站 Profile 只回傳通過的股票；未通過者不能由一般API執行。
6. **更新前端名稱**：若希望有固定快捷按鈕或舊畫面也能顯示中文名稱，再更新 `前端/src/features/multiBacktestModel.js`。主要新畫面會優先使用後端 `stock_name`。

## 預檢內容

- 股票必須同時存在於 `stock_universe` 與 `datasets`。
- 設定日期須通過共用研究日期鎖；2025/07/01～2025/12/31及2026/07/01起不會因資料接入而解鎖。
- SQLite 須有 `market_kbars`，必要欄位為 `stock_code`、`freq_minutes`、`kbar_timestamp`、`open`、`high`、`low`、`close`、`volume`。
- 完整交易日為台北時間09:00～13:25共54根5分K；不可缺棒、重複、錯序或含無效OHLCV。
- 三模型都必須有合法、同股票、可追溯且早於進場時間的預測；機率須有限、介於0～1、加總為1，分類須等於最高機率類別。
- 固定模型推論的訓練目標截止日不得晚於訊號日或2024/12/31；OOF資料須符合既有時間順序Fold。
- 大盤日期須唯一且依序排列，收盤價必須為正值。
- 股利事件須含 `ex_date`、`payment_date`、`cash_per_share`，日期與金額必須合法。
- 至少要有一天同時具備完整個股行情及RF、XGBoost、GRU三模型合法預測，否則不能開放。

`QA_PASSED` 只代表網站資料整合格式通過，不代表資料來源已由第三方獨立稽核，也不代表策略有效或獲利。

## 2025年的資料角色

- 2025/01/01～2025/06/30是已使用的 Validation；可以作歷史驗證，但不得宣稱全新、完全未看過的樣本外結果。
- 2025/07/01～2025/12/31是 Additional Holdout，一般網站與資料預檢不得存取。
- 2025全年包含已見上半年與保留下半年，兩者必須分開執行、分開報告，不能合併宣稱為乾淨樣本外測試。

## 正式驗證授權範圍

既有正式授權只適用已凍結的4938單一實驗，不能沿用到其他股票、策略或日期。新增股票若要使用2025下半年，必須由使用者再次明確要求該股票的正式 Holdout Test，並在首次存取前完成：

1. 凍結程式、策略、模型、股票、日期、成本、資金及判定標準。
2. 建立獨立實驗ID、來源雜湊、授權紀錄及不可重置的 `consumed` 標記。
3. 第一次資料存取前即標示已使用；失敗也不能恢復為未看過。
4. 保存全部結果，不依結果回頭修改後重測同一保留期間。
5. 保持一般網站日期鎖不變；正式流程不得變成通用解鎖入口。
