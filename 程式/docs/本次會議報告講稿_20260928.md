# 本次會議報告講稿

預計時間：約 4～5 分鐘。

## 報告前先開啟的分頁

1. `exports/cross_stock_dashboard_latest.html`
2. `exports/clean_validation_latest.html`
3. `exports/ml_baseline_latest.html`
4. `http://localhost:8081`
5. `docs/0925-0927的進度說明.md`（備用）

---

老師好，我們這次主要延續上次的建議，完成四個方向：市場階段分析、固定策略參數、跨股票驗證，以及前端與資料庫整合。

首先，在市場階段分析方面，我們把行情分成上漲、盤整、下跌及資料不足四種狀態，而且只使用當天以前的資料判斷，避免使用未來資料。

分析後發現，聯電原本的高報酬主要集中在上漲階段。以三指標多數決為例，總報酬約為正 75.10%，其中上漲階段貢獻約 55.09%，盤整和下跌階段的貢獻明顯比較少。

因此，我們目前不能只根據聯電的總報酬，就認定策略在所有行情或股票都有效。

> **此時展示：** `exports/cross_stock_dashboard_latest.html`。先選聯電，再指出三指標多數決及市場階段數據。

第二，我們固定了策略參數，並建立設定檔檢查碼，避免看到結果後反覆修改。資料也分成開發資料、乾淨驗證、已看過的驗證資料及最終 Holdout。

其中，2025 年 7 月到 12 月仍然保持鎖定，目前沒有回測或查看這段期間的績效。回測、報告和資料庫同步入口也都有日期檢查，避免不小心使用保留資料。

第三，我們將相同參數套用到其他股票，檢查策略是否具有泛化能力。

第一輪測試包含台積電、中華電、富邦金、國泰金和中鋼。結果顯示，聯電的高報酬沒有穩定出現在其他股票。例如台積電六種策略全部虧損，部分股票即使有正報酬，也沒有超越同期買進持有。

所以我們後來不再只看最高報酬，而是同時檢查報酬中位數、獲利股票數、交易成本、Profit Factor、Sharpe Ratio、最大回撤，以及是否超越買進持有。沒有策略通過時，系統會顯示「暫不交易」，不會勉強挑一個結果最好看的策略。

> **此時仍展示：** `exports/cross_stock_dashboard_latest.html`。切換不同股票，讓老師看到同一策略在不同股票上的差異及「暫不交易」判定。

接著，我們分別診斷六種策略的問題。RSI 的主要問題是交易頻繁及進場優勢不足；MACD 和三指標多數決則容易在盤整或弱勢行情中產生錯誤訊號。

我們測試了日線趨勢濾網、冷卻時間、移動停利和早期價格延續確認。MACD 與三指標多數決在開發資料上有改善，因此被保留為研究候選。

不過，我們再使用鴻海、廣達、兆豐金、玉山金、統一、台泥、和泰車及台塑化八檔未參與策略設計的股票進行 Clean Validation，最後兩個候選都沒有通過。

MACD 候選平均報酬約負 0.85%，只有兩檔股票獲利；三指標多數決候選平均報酬約負 4.13%，八檔股票都沒有獲利。

這次結果雖然不好看，但它證明聯電上的高報酬不能直接推廣到其他股票。目前我們沒有足夠證據把任何策略稱為通用正式策略。

> **此時展示：** `exports/clean_validation_latest.html`。指出 MACD 與三指標多數決的平均報酬、獲利股票數和 FAIL 判定。

第四，我們完成了網站、Node.js API、Python 回測與 MySQL 資料庫的整合。

網站目前具有註冊登入、市場行情、股票搜尋、自選股、策略分析及歷史報告功能。使用者可以輸入股票代號，選擇 MA、RSI、MACD、布林通道、區間突破或三指標多數決，再從網站直接執行 Python 回測。

回測完成後，系統會將報酬、勝率、Profit Factor、Sharpe Ratio、最大回撤、交易成本及交易紀錄存入 MySQL，並在前端顯示摘要與完整 HTML 報告。

我們也修正了策略設定誤用、報酬與最大回撤欄位對應，以及每位使用者報告分開保存等問題。前端和 Python 端都保留 Holdout 日期限制。

> **此時展示：** `http://localhost:8081`。依序快速展示首頁行情、自選股及分析頁；在分析頁切換六種策略，若現場回測耗時，就展示已保存的歷史報告，不必現場重新執行。

另外，我們建立了 Random Forest、XGBoost 和 GRU 三種機器學習 Baseline，並使用相同的輸入、預測目標和資料切分進行比較。

目前 GRU 的整體結果相對平衡，但 ROC AUC 約為 0.598，預測能力仍然偏弱。XGBoost 雖然正確率較高，但低於「永遠猜不漲」的簡單基準，因此不能只看正確率就認定模型有效。

目前 ML 只作為研究比較，還沒有直接轉成交易訊號。LLM 也只負責將策略、模型和風險資料整理成容易閱讀的文字，不會修改績效、買賣訊號或直接下單。

> **此時展示：** `exports/ml_baseline_latest.html`。指出三模型比較、永遠猜不漲基準，以及目前仍屬初步結果。

綜合來說，這次主要完成的不是繼續把聯電的報酬調高，而是確認聯電結果具有行情依賴，並透過跨股票和 Clean Validation 找出策略泛化不足。同時，我們也將研究流程、前端、API、資料庫、Python 回測及 ML Baseline 整合成一套可以操作和追蹤的系統。

下一步，我們預計將研究範圍明確縮小到科技產業，因為目前的均線、動能和突破策略，理論上可能比較適合波動與成交量較明顯的股票。

不過，我們會在執行以前先固定科技股清單、策略版本、回測期間和通過標準。同一策略在所有股票使用相同參數，也會完整公布所有結果，不會看到績效後才刪除表現不好的股票。

已經測過的聯電、台積電、鴻海、廣達及聯發科，只會列為開發或已看過的資料，不會再當成新的乾淨驗證。

評估時除了報酬，也會比較中位數、交易成本、回撤、獲利股票數，以及是否超越個股買進持有和科技產業基準。前端也預計加入多檔科技股、不同市場階段和策略推薦狀態的比較畫面。

如果科技股仍然沒有一致效果，我們會保留失敗結論，不再繼續縮小範圍或反覆調參。最終 Holdout 會繼續鎖定，等研究規則完全固定後才進行正式測試。

以上是我們這次的進度與下一步規劃。

## 老師可能追問的簡短回答

### 現在最好的策略是哪一個？

如果只看聯電開發期間，是三指標多數決；但它在八檔 Clean Validation 中沒有通過，所以目前沒有足夠證據認定任何策略是通用最佳策略。

### 為什麼失敗結果也算進度？

因為它排除了把聯電上漲行情的高報酬誤認為策略具有泛化能力。目前已經能確認問題與進場優勢、交易成本和行情適配有關。

### 改測科技股是不是繼續挑有利資料？

我們會先固定科技股範圍、股票清單和判定標準，再一次性執行。已經看過的股票不會冒充新的驗證資料，不同股票也不會使用不同參數。
