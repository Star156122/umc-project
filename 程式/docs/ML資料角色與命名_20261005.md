# ML 資料角色與命名

自 2026-10-05 起，現行 ML Trading 統一使用以下名稱。程式中的 `test` 已改名為 `development`，因為 2026 上半年已參與 V1、V2、V3 開發，不能再稱為獨立 Test。

|程式鍵值|報告名稱|期間|目前權限|用途|
|---|---|---|---|---|
|`train`|Training|2023-01-01～2024-12-31|允許|模型擬合與標準化|
|`validation`|Validation|2025-01-01～2025-06-30|允許|Early Stopping 與開發期驗證|
|`development`|Development|2026-01-01～2026-06-30|允許、已看過|V1、V2、V3 模型與交易結果比較|
|`holdout`|Additional Holdout|2025-07-01～2025-12-31|`forbidden`|額外保留資料|
|`final_out_of_sample`|Final Out-of-Sample Test|2026-07-01～目前可取得的最新資料|`forbidden`|時間順序上的最終樣本外測試|

## 命名規則

- `test` 不再作為現行 ML 開發程式的資料鍵值。
- 歷史 `exports/` 結果可能仍含有 `test` 欄位，這只是當時輸出格式；它的正確研究身分是 Development，歷史檔不重寫。
- `Training`、`Validation` 與 `Development` 是目前唯一允許模型開發讀取的角色。
- `Additional Holdout` 與 `Final Out-of-Sample Test` 都不能用於訓練、調參、特徵選擇、模型比較、除錯績效或報告產生。

## 程式防線

- 正式政策：`configs/ml_data_policy.json`
- ML 日期檢查：`ml/data_roles.py`
- 現行資料入口：`ml/trading_pipeline.py`
- 匯入入口：`scripts/import_ml_kbars.py`
- 防線測試：`tests/test_ml_data_roles.py`

ML 資料入口會在資料庫查詢或外部下載以前先檢查日期。政策沒有環境變數、命令列參數或設定檔解鎖開關。

## 既有研究紀錄

2026-07-01～2026-09-24 曾被技術指標的行情切換研究查看，因此專案登記表仍誠實保留為技術研究的 `validation_seen`。本次新規則表示該期間禁止作為 ML 開發輸入；不會回頭把既有技術研究歷史改寫成未看過資料。

本次只整理角色、名稱與防線，沒有重新訓練、回測、修改 Features、Label、模型參數或交易規則，也沒有查詢兩個保留區的行情涵蓋情況。
